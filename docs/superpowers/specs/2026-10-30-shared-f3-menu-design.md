# Общее меню F3: Minimap и HR Department

Дата: 2026-10-30. Статус: проектирование и план, без изменения исполняемого кода.

## Цель и согласованные требования

F3 открывает одно полноценное меню настроек установленных совместимых модов. Есть свободный видимый курсор, неподвижная от мыши камера и блокировка игрового управления. Пользователю не требуется сначала открывать телефон или паузу. Новые моды добавляют собственную панель по опубликованному протоколу; существующие моды не обновляются ради нового участника. Каждый мод работает отдельно, без Phone App, другого нашего мода или дополнительной обязательной DLL.

F4 сохраняет диагностику Minimap. Настройки и их существующие ключи сохраняются. Phone App остаётся дополнительным интерфейсом к тем же значениям. HR сохраняет семантику скоростей/лимитов версии1.2.0. Игровое время сохраняет штатное поведение; меню само не меняет Time.timeScale.

## Рассмотренные подходы

1. Отдельные клавиши/окна: проще, но не выполняет согласованное единое меню и расширение.
2. Общая обязательная DLL: проще единый типовой API и единственный хозяин F3, но создаёт ещё одну устанавливаемую зависимость.
3. Встроенный общий компонент + совместимый протокол + выбор одного хозяина: согласованный подход. Каждый DLL самодостаточен, цена — явная межсборочная совместимость и проверка выбора хозяина.

Один раз обновляем Minimap и HR. Старый Minimap без нового протокола продолжит независимо читать F3; полностью согласованная работа требует этой пары обновлений. Будущие участники протокола V1 не требуют правки этих двух модов.

## Регистрация и совместимость V1

В каждой сборке — public static класс Skoofidons.SharedSettings.EntryPointV1 с методом GetManifestV1(): IDictionary<string, object>. Поиск только по зарегистрированным Melon-сборкам, не по файлам Mods и не с загрузкой неизвестных DLL. Общий тип из отдельной contract-DLL не нужен: при одинаковом namespace типы разных сборок всё равно имеют разную идентичность.

Обязательные поля manifest:

| Ключ | Тип CLR | Значение/смысл |
| --- | --- | --- |
| contract | string | Skoofidons.SettingsMenu/1 |
| id | string | skoofidon.minimap или skoofidon.hr; для новых модов свой стабильный уникальный ID |
| title | string | Видимое название мода |
| providerVersion | string | Числовая версия, читаемая System.Version |
| hostVersion | string | Версия встроенного runtime, сначала1.0.0 |
| minimumHostVersion | string | Минимальный совместимый runtime, сначала1.0.0 |
| draw | System.Action | Нарисовать содержимое панели в области, подготовленной хозяином |
| opened | System.Action | Синхронизировать панель с текущими preferences при первом выборе в этой сессии |
| closed | System.Action | Один раз завершить UI-сессию посещённой панели, сбросить отложенную запись |

Поля contract/id/title/версии/callbacks валидируются; неизвестные дополнительные поля игнорируются. Callback не принимает Unity-объекты или собственные contract-типы между сборками. Полученный делегат должен быть именно CLR System.Action, не одноимённая Il2CppSystem.Action. Draw не управляет F3, курсором, состояниями игры или наружным окном.

Сначала каждый мод инициализирует Config и manifest. После завершения общей фазы инициализации строится одинаковый снимок участников. Выбор хозяина: максимальная hostVersion среди совместимых V1, затем ID и полное имя сборки по Ordinal как устойчивое разрешение равенства. Дубликаты provider ID обрабатываются детерминированно: максимальная providerVersion, затем имя сборки; один ID — один раздел и одна строка предупреждения. Это не заменяет правила MelonLoader о дублирующихся модах.

Только выбранная сборка читает F3 и рисует окно. Остальные передают свои callback-панели и не создают отдельные обработчики. Проверка выбора опирается на одинаковый полный снимок, а не на случайный порядок OnUpdate. На каждом кадре повторного обхода сборок нет. Установка новых модов предполагает перезапуск игры; hot-loading DLL не входит в первый выпуск.

Новый runtime обязан сохранять обнаруживаемый V1 endpoint и обслуживать старые панели. Добавление модов и совместимых minor-возможностей не требует обновления старых DLL. Несовместимый новый major сам по себе этого не гарантирует: ему нужен V1-адаптер. Некорректный manifest не участвует; не включать для него второе окно на F3. Фатальный сбой хозяина закрывает меню и освобождает принадлежащие ему ресурсы; автоматический hot-failover во время открытого меню не входит в V1.

Общий исходный компонент хранится канонически в HR: SharedSettings/V1/*.cs. Его копия с тем же хешем содержится в MinimapMod/SharedSettings/V1/*.cs. Каждая копия включается в собственную сборку; сборка одного репозитория не читает соседний checkout. Обновлять обе копии при добавлении третьего мода не требуется. Обновления самого runtime сопровождаются версией и тестами старого участника против нового хозяина.

## Окно и жизненный цикл ввода

Одно окно с прокручиваемым списком модов слева и выбранной панелью справа; при одном участнике сразу видны его настройки. opened вызывается один раз при первом посещении provider в текущей сессии окна; переключение разделов не вызывает closed и не отбрасывает HR draft. При окончательном закрытии closed вызывается ровно один раз для каждого посещённого provider, даже если сейчас выбран другой. Запоминается последний выбранный ID, при его отсутствии выбирается первый раздел по title/ID. Список масштабируется по высоте и не превращается в неограниченную строку вкладок. Внутри HR: Botanist, Chemist, Cleaner, Handler, Fixer, Machine Timers.

Состояния сессии: Closed → Opening → Open → Closing → Closed; отдельное Suspended/ClosingDeferred, если поверх появилось чужое native-состояние. Один frame не обрабатывает одно нажатие дважды. F3, Escape и кнопка закрытия используют один путь RequestClose. Ввод в игровых чате/консоли не должен случайно открывать настройки; внутри собственного окна закрытие остаётся доступным.

До показа панели хозяин получает InputLease через отдельный адаптер GameUiInputLease. Он создаёт собственное native MonoState, не меняет общие статические пресеты StateProperties и использует штатный переход состояния для свободного курсора, заблокированных камеры/движения/экипировки/инвентаря. Нужные значения берутся из копии пресета, а не записываются в общую UIDefault. Конкретный родитель для Main/Menu, создание IL2CPP-компонента, exit-приоритет и минимальная связка с UIScreen подтверждаются обязательным этапом1.

Открытие допустимо только после успешной атомарной регистрации ввода; при частичном сбое откатить свои регистрации и не показывать незащищённое окно. Обычное закрытие завершает callback и освобождает lease в finally. Освобождение снимает только своё верхнее состояние; если сверху чужое — скрывает/приостанавливает F3 и откладывает снятие до возврата собственного наверх. Ни одного чужого Pop, очистки стека или принудительного LockMouse(true).

Escape потребляется только для верхнего собственного меню через native exit-маршрут; одно нажатие не закрывает F3 и телефон/паузу под ним. Нажатия/колёсико, клики закрытия и удерживаемые клавиши не проходят в игру в кадре открытия/закрытия. После скрытия панели lease продолжает удерживаться через release-barrier до отпускания управляющего ввода; правильность порядка native transitions/input callbacks — обязательный gate этапа1. При потере фокуса, смене сцены, исключении renderer и выходе — единый путь завершения с проверкой существования native-ссылок. При уничтожении всей сцены не пытаться снимать элементы уже исчезнувшего стека. Обработчики и ссылки очищаются идемпотентно.

Если renderer одного provider сломал IMGUI-пары Begin/End, закрыть текущую сессию с освобождением ввода, отметить неисправную панель и позволить заново открыть остальные. Не продолжать повреждённый layout в том же кадре и не спамить лог.

## Настройки и необязательный телефон

Общая оболочка отвечает за список, F3 и ввод; настройки принадлежат своим модам. Вызов применения переносится из Phone App callback в обычный service. Панель и дополнительный phone-адаптер используют один путь применения и существующие MelonPreferences-ключи.

Решение для первого выпуска, предложенное автором плана: Minimap сохраняет мгновенное применение и debounce0.5с; closed вызывает FlushPendingSettings. В HR поля редактируются в draft, кнопка «Применить» проверяет весь draft, переносит значения в Config, сохраняет и применяет через общий service. Закрытие до применения отбрасывает draft; это явно подписано в панели. Ошибки записи видны пользователю, ввод остаётся закрываемым. Все актуальные HR-параметры доступны, включая Fixer/лимиты/машины; числовой ввод не ограничивает значения случайным диапазоном slider. Не менять диапазоны/семантику экономики и действительность существующих значений побочно.

Типизированные ссылки на Phone App удаляются из обеих runtime-сборок и build-reference. Опциональный адаптер находит уже загруженную Melon-сборку и связывает события reflection/delegate с проверкой сигнатуры, хранит точные delegates для отписки. Для HR category-order также отсутствует typeof(ModSettingsEvents). Отсутствие/несовместимость телефона отключает только этот адаптер. Безопасность отсутствия DLL проверяется отдельным запуском/проверкой ссылок, а не только if в исходнике.

## Приёмка и границы

Нужны автономный HR, автономный Minimap, оба вместе, оба без Phone App, с Phone App; третий тестовый provider без пересборки первых двух; старый runtime1.0 + новый совместимый1.1 при прежних DLL; перестановка порядка загрузки; повтор F3/удержание; ошибка manifest/render; главное меню/игра/телефон/пауза/смена сцены/потеря фокуса; мышь, камера, движение, взаимодействие и Escape без проходящих действий; существующие preferences и регрессии HR176/Minimap tracking.

Первый этап должен доказать корректность native InputLease отдельно. Пара кандидатных сборок выпускается вместе для одиночного теста, публикация стабильных версий — после результата пользователя. Горячая установка DLL, сторонние моды без протокола V1, пауза симуляции, переделка всех настроек в универсальные схемы, gamepad-навигация нового IMGUI и кооператив не входят в первый выпуск.

## Уточнения при реализации 2026-10-31

- В публичном V1 ID состоит из строчных ASCII a–z, цифр, точки, дефиса и подчёркивания, длина1–128; title непустой, до128 символов. Версии числовые System.Version, недостающие build/revision нормализуются к0.
- Для аварийной очистки найден отдельный MonoState.RemoveFromDefaultParent / MonoStateMachine.Remove(IState): удаляется именно своё состояние, чужое верхнее остаётся. Обычное закрытие по-прежнему проходит release-barrier/проверку верхнего состояния.
- Объект диагностического native-state привязан к transform владельца SceneState. Выгрузка посторонней additive-сцены не считается уничтожением владельца. Сначала удаляется своё состояние, затем снимается Escape, затем уничтожается объект; ошибки сохраняют этапы для повторной очистки.
- F6 probe — техническая панель, не финальная внешность. Итоговое F3 требует просторного центрированного окна, чёткой иерархии, читаемых полей и отступов, прокрутки списка модов/разделов. Старую узкую рамку Minimap не переносим.
- Native-проверка пользователем пока недоступна. Это не отменяет gate; продуктовая оболочка и перенос панелей не включены.
