# Выполнение: два параметра скорости, 1.1.0-beta.3

База f1860c1, текущая ветка codex/botanist-timing-and-layout. По прямому запросу пользователя у четырёх специальностей одинаковые две настройки: передвижение и работа. Общий Work speed ботаника заменяет переключатель и пять отдельных множителей. Новые процессы, автоматические таймеры станков и кооператив в эту доработку не входят.

- До реализации новые тесты дали RED: timing 39/41 (нет RequiresPatch), фактическая beta.2 30/31 (нет BotanistWorkSpeed). После реализации GREEN: timing 41/41, реальная DLL 31/31. Проверяется отсутствие лишних скоростных полей и enable-флага, а также отсутствие регистрации при 1/невалидном значении и автоматическое включение при ускорении/замедлении.
- Повторены неизменённые политики employee 12/12, Cleaner 8/8, layout 43/43. Всего 135. Release 0 ошибок/предупреждений; API 216 внешних ссылок, 13 автоматических Harmony-целей, 0 ошибок.
- Все пять распознаваемых действий ботаника читают один Config.BotanistWorkSpeed. Прежний селектор отдельных значений и enable-проверки удалены. Общий WorkSpeedMultiplier по умолчанию 1; остальные профессии используют прежние ключи и тот же текст пункта.
- Прежние разные коэффициенты ботаника не объединяются: новый общий ключ начинается с 1. Это решение записано в плане и сценарии; предпочтения перед установкой сохраняются отдельно. Старые поля не регистрируются и не используются.
- Независимый обзор не выявил Critical/Important/Minor регрессий. По локальному IL MelonLoader зарегистрированные Entries создаются через CreateEntry, а оба интерфейса Phone App перечисляют Category.Entries: оставшиеся старые CFG-ключи сами по себе не возвращают удалённые пункты.
