# Выполнение расширения строк станций Handler

База: локальная ветка codex/handler-route-counter, commit 9e7d084, HR 1.0.3. Прямой запрос пользователя: больше 10 станций, все корректно отображаются с прокруткой. Используются текущий checkout и ветка; отдельный worktree не требуется, публикация не запрошена.

- Pre-flight: один связанный этап, общие интерфейсы между независимыми задачами отсутствуют. План/спецификация сохранены перед кодом; реализация выполняется inline по навыкам writing-plans / executing-plans / test-driven-development.
- Исследование: ObjectListFieldUI.Bind вызывает Refresh, затем регистрирует RemoveEntryClicked(index) для каждого Entries[i] и скрывает roots с индексом >=MaxItems. Native Refresh заполняет Title/Icon/Remove, но не включает корневой объект строки. Prefab содержит десять RectTransform-строк и VerticalLayoutGroup на Contents; кнопка каждой строки называется Remove.
- RED 14/19 на DLL 1.0.3: расширение строк отсутствует. GREEN 19/19 после реализации управляемого allocation/rollback и Unity-адаптера.
- Ruling: создавать строки по реальному SelectedObjects.Count, не по MaxStations — большие настройки без назначений не выделяют объекты; существующие назначения не обрезаются при снижении лимита.
- Ruling: клонированные onClick заменяются пустым событием перед native Bind; во время Bind новые строки оставляют регистрацию игре, после Bind получают один управляемый callback с реальным индексом. Исходные десять событий остаются штатными.
- Первичная попытка обойти скрытие over-limit через повторный native Refresh была недостаточна. Ревью выявило P1: root клона остаётся неактивным, Refresh включает только детей. Слабая проверка наличия вызова Refresh удалена.
- Исправление ревью: явная SetAssignedVisibility по фактическому числу назначений, применяемая реальным Unity-адаптером после Refresh/Bind; перед повторным Bind восстанавливается исходная активность roots для штатного multi-edit. Новые проверки поведения видимости и границы адаптера: RED 19/21 → GREEN 21/21. Неиспользуемые строки скрыты, назначенные остаются активны независимо от текущего лимита.
- Статическое ревью не нашло других actionable замечаний. Проверки Unity-rendering, нативных callback, прокрутки и save/reload остаются игровыми и описаны в отдельном сценарии.
