# Skoofidon's HR Department 1.2.0

Stable update for **Schedule I0.4.7f12 IL2CPP**, MelonLoader **0.7.3**, Mod Manager & Phone App **2.2.4**. Singleplayer.

## Changes since1.1.0

- Seven independent controls in **Machine Timers**: Chemistry, Oven, Mixing (both station versions), Cauldron, Drying, Plant growth and Mushroom growth. Default1;7 gives seven times the affected progress rate,0.5 half. Higher means less time.
- Five machines capture the configured factor when a new batch starts. Changing settings leaves that batch's factor intact; save/load retains it. Existing/unrecognized batches without metadata use1. Drying batches retain independent factors, and machine ETA displays reflect captured rates.
- Plant and mushroom factors apply to the next native growth calculation for **all growing cultures**, including existing and loaded crops. Only future growth is scaled: accumulated progress does not jump. No extra per-crop factor bookkeeping is used.
- Settings order: **Botanist → Chemist → Cleaner → Handler → Fixer → Machine Timers**. Existing preference identifiers and values are preserved.
- Employee Move/Work speed, assignment limits, route counter and scrolling from1.1.0 remain included. Native environmental checks, quantities, water timing and fixed employee pauses remain independent.

Completion remains quantized by native ticks. Drying preserves the native one-quality-transition-per-call limit on large time skips. Co-op configuration synchronization and property capacity changes remain deferred.

## Installation and upgrade

1. Close the game. Keep all prior HR DLLs, including .dll.disabled backups, **outside Mods**; back up MelonPreferences.cfg.
2. Copy only **SkoofidonsHRDepartment.dll** into Mods. Keep one HR DLL there. Do not install game/loader dependencies from build output.
3. Start the game and confirm HR1.2.0 in the log. Save Phone App settings to apply chosen values. Existing preference keys retain their values; newly introduced machine factors default to1 on upgrade from1.1.0.

Removing the mod preserves native progress; its additional machine metadata is ignored and may be discarded by a subsequent save. Keep backups if rollback is needed.

Earlier beta.1 machine checks also reported no problems.
