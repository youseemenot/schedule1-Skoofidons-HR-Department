# Release priorities after1.3.0

1.3.0 provides independent/shared F3 settings and current-tab reset. Future releases must bring visible player value and honest change descriptions; confirmed failures receive timely fixes.

Proposed next useful update, roughly1–2weeks after1.3.0 if feedback and testing support it: address reproducible settings readability/input issues across resolutions and RU/EN, and compatibility after game updates. Gather original gameplay/menu screenshots and concise usage examples so players can understand employee Work speed versus machine/growth speed. Do not turn documentation-only polish into a claimed new gameplay feature.

Minimap's next independent update can adopt the common menu and reset directly in its own DLL, so its standalone installation gets the same UI without needing HR. That is separate Minimap work, not bundled as a requirement for HR users. Property capacities, co-op synchronization and additional features require their own confirmed demand, API research and test matrix.

For each release record tested game/loader/mod combinations, reported issues, actual downloads/feedback and the reason to update. Platform visibility/monetization effects are not assumed. The workspace-wide `MOD_CATALOGUE_PLAN.md` owns catalog promotion and metrics; no artificial feature withholding or meaningless version churn.
