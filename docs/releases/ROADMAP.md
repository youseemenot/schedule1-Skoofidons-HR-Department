# Release priorities after 1.3.2

1.3.2 preserves F3 graphics through repeated world loads. Independent/shared F3 settings and current-tab reset remain available. Future releases must bring visible player value and honest change descriptions; confirmed failures receive timely fixes.

Proposed next useful update, roughly 1–2 weeks after 1.3.2 if feedback and testing support it: address confirmed assignment, settings persistence or readability/input issues across resolutions and RU/EN, and compatibility after game updates. Gather original gameplay/menu screenshots and concise usage examples so players can understand employee Work speed versus machine/growth speed. Do not turn documentation-only polish into a claimed new gameplay feature.

Minimap 2.3.0 now embeds the common menu and reset in its own DLL; neither mod requires the other or Phone App. Minimap's next research priority is co-op join/leave/reconnect behavior, with changes driven by actual findings. Property capacities, HR co-op synchronization and additional features require their own confirmed demand, API research and test matrix.

For each release record tested game/loader/mod combinations, reported issues, actual downloads/feedback and the reason to update. Platform visibility/monetization effects are not assumed. The workspace-wide `MOD_CATALOGUE_PLAN.md` owns catalog promotion and metrics; no artificial feature withholding or meaningless version churn.
